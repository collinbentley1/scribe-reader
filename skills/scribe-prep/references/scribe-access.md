# Scribe access and output

Cloud backup, rendered notebook pages, an exported PDF, a delivered companion, and native editing are different capabilities. Use the account's verified configuration. Cloud reading does not establish that a device uploaded its latest writing.

The bundled reader performs authenticated read-only GET requests and preserves original page images. It implements no native notebook writer. Credentials, captures, receipts, and preparation state remain outside the public repository.

Amazon documents explicit notebook exports to Google Drive or Microsoft OneDrive on eligible models. This does not establish continuous synchronization or original-notebook editing. Check current [Amazon export documentation](https://digprjsurvey.amazon.com/csad/help/node/TP8wuaQilIlwlITVTL) before relying on model eligibility.

An explicitly shared handwritten PDF or image preserves checkboxes and grouping for review. Sharing by email requires another share after writing changes. Follow [email intake](email-intake.md) and Amazon's [notebook sharing guide](https://digprjsurvey.amazon.com/csad/help/node/TJE2UYmdw0ppUuR3Rs).

The PDF companion is a separate document. An authorized document can use official Send to Kindle, but upload acceptance, library availability, and device receipt require separate observations. Imported Drive documents are copies, and annotations do not automatically synchronize back. See [Amazon import behavior](https://digprjsurvey.amazon.com/csad/help/node/TjrMJmg3DZpAQLwVuN).

Native cloud writeback remains unimplemented and unverified. Historical users reported replacing an existing editable notebook over USB and subsequent synchronization. That is a research lead, not proof of a cloud API for generating and merging ink. See the [firsthand replacement report](https://www.mobileread.com/forums/showpost.php?p=4391735&postcount=635). Do not modify notebook files or guess write endpoints during preparation.
